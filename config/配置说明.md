# 配置文件说明

## 配置文件结构

```
config/
├── config.yaml              # 主配置（数据库连接、时间范围、目录配置）
├── config.example.yaml      # 配置示例
└── tasks/                   # 稽核任务配置目录
    ├── operation_log.yaml   # 4A操作日志表稽核任务
    ├── gold_log.yaml        # 4A金库审批日志表稽核任务
    └── special_statistics.yaml  # 特殊统计稽核任务
```

---

## 配置方式说明

### 任务化配置（当前方式）✅

**优点**：
- 配置结构清晰，每个稽核任务一个文件
- 支持自定义参数传递给SQL模板
- 灵活的子任务配置
- 支持多表稽核

**配置文件**：
- `config/config.yaml` - 数据库连接、时间范围、目录配置
- `config/tasks/任务名.yaml` - 稽核任务配置（表信息 + 子任务列表）

**使用命令**：
```bash
python main.py --task operation_log          # 执行操作日志稽核任务
python main.py --task gold_log               # 执行金库日志稽核任务
python main.py --gen-sql --task gold_log     # 生成金库日志的大SQL
python main.py --all-tasks                   # 执行所有稽核任务
```

### 2. config/tasks/任务名.yaml（稽核任务配置）

**示例：config/tasks/gold_log.yaml**

```yaml
# 稽核任务名称（第一级配置）
task_name: "4A金库审批日志表稽核"

# 表信息配置
table_info:
  name: "gold_log"                                    # 表标识（必需）
  display_name: "4A金库审批日志表"                     # 显示名称（必需）
  description: "4A系统金库审批日志数据质量稽核"         # 描述（可选）
  
  # 表名配置（必需）
  standard_table: "argus.bg_4a_gold_log_standard"
  error_table: "argus.bg_4a_gold_log_error"
  
  # 字段配置（必需）
  time_field: "generic_into_time"                     # 时间字段
  primary_key: "gold_grant_result"                    # 主键
  
  # SQL模板目录（必需）
  template_dir: "gold_log"                            # sql_templates/gold_log/
  
  # 特殊过滤条件（可选）
  filter_condition: "standby1 IS NULL"                # 过滤测试数据

# 子任务列表（任务化配置）
tasks:
  # 任务1：金库授权结果-唯一性检查
  - task_id: "gold_grant_result_uniqueness"
    task_name: "金库授权结果唯一性检查"
    enabled: true
    sql_template: "gold_log_uniqueness_check"
    params:
      field: "gold_grant_result"
      display_name: "金库授权结果"
  
  # 任务2：金库授权结果-非空检查
  - task_id: "gold_grant_result_null"
    task_name: "金库授权结果非空检查"
    enabled: true
    sql_template: "gold_log_null_check"
    params:
      field: "gold_grant_result"
      display_name: "金库授权结果"
  
  # 任务3：审批人ID-条件非空检查
  - task_id: "approved_user_id_conditional_null"
    task_name: "审批人ID条件非空检查"
    enabled: true
    sql_template: "gold_log_conditional_null_check"
    params:
      field: "approved_user_id"
      display_name: "审批人ID"
      condition: "gold_grant_type != '按时间段' AND gold_exec_result NOT IN ('审批不通过', '未触发金库')"
  
  # 任务4：开始时间-条件非空检查
  - task_id: "start_time_conditional_null"
    task_name: "开始时间条件非空检查"
    enabled: true
    sql_template: "gold_log_time_conditional_null_check"
    params:
      field: "start_time"
      display_name: "开始时间"
      condition: "gold_grant_type = '按时间段'"
```

**配置项说明**：

| 配置项 | 必需 | 说明 |
|--------|------|------|
| `task_name` | ✅ | 稽核任务名称（显示在日志中） |
| `table_info.name` | ✅ | 表标识符 |
| `table_info.display_name` | ✅ | 表显示名称 |
| `table_info.standard_table` | ✅ | 标准表全名 |
| `table_info.error_table` | ✅ | 错误表全名 |
| `table_info.time_field` | ✅ | 时间字段名 |
| `table_info.template_dir` | ✅ | SQL模板目录名 |
| `table_info.filter_condition` | ❌ | 特殊过滤条件 |
| `tasks[].task_id` | ✅ | 子任务ID（唯一标识） |
| `tasks[].task_name` | ✅ | 子任务名称 |
| `tasks[].enabled` | ✅ | 是否启用（true/false） |
| `tasks[].sql_template` | ✅ | SQL模板名称（不含后缀） |
| `tasks[].params` | ✅ | 自定义参数（传递给SQL模板） |

## SQL模板中的占位符

SQL模板使用 `{占位符}` 格式，系统自动替换：

### 系统自动提供的占位符

| 占位符 | 来源 | 说明 |
|--------|------|------|
| `{start_time}` | `config.yaml` | 稽核开始时间 |
| `{end_time}` | `config.yaml` | 稽核结束时间 |
| `{table_standard}` | `tasks/任务名.yaml` 的 `table_info` | 标准表名 |
| `{table_error}` | `tasks/任务名.yaml` 的 `table_info` | 错误表名 |
| `{time_field}` | `tasks/任务名.yaml` 的 `table_info` | 时间字段名 |

### 任务自定义占位符

在 `tasks[].params` 中配置的任何参数都可以在SQL模板中使用：

| 占位符 | 来源 | 说明 |
|--------|------|------|
| `{field}` | `tasks[].params.field` | 字段名 |
| `{display_name}` | `tasks[].params.display_name` | 字段显示名称 |
| `{condition}` | `tasks[].params.condition` | 条件表达式 |
| `{任意参数}` | `tasks[].params.任意参数` | 自定义参数 |

**示例SQL模板**：

```sql
-- 条件非空检查 - 统计版本
SELECT 
    dst_device_type,
    COUNT(*) AS total_count,
    SUM(CASE WHEN {field} IS NULL AND ({condition}) THEN 1 ELSE 0 END) AS null_count
FROM {table_standard}
WHERE {time_field} >= '{start_time}' 
  AND {time_field} < '{end_time}'
GROUP BY dst_device_type;
```

## 使用示例

### 示例1：执行单个稽核任务

```bash
# 1. 编辑 config/config.yaml，设置数据库连接和时间范围
# 2. 配置已存在：config/tasks/gold_log.yaml
# 3. 执行稽核
python main.py --task gold_log

# 或生成大SQL
python main.py --gen-sql --task gold_log
```

### 示例2：添加新的稽核任务

```bash
# 1. 复制现有配置作为模板
cp config/tasks/gold_log.yaml config/tasks/new_task.yaml

# 2. 编辑 config/tasks/new_task.yaml
#    - 修改 task_name（稽核任务名称）
#    - 修改 table_info 中的表名、字段等
#    - 修改 tasks 中的子任务配置

# 3. 创建SQL模板目录
mkdir sql_templates/new_task

# 4. 复制SQL模板
cp sql_templates/gold_log/*.sql sql_templates/new_task/

# 5. 根据新表结构修改SQL模板

# 6. 执行稽核
python main.py --task new_task
```

### 示例3：执行所有稽核任务

```bash
python main.py --all-tasks
```

系统会自动读取 `config/tasks/` 目录下的所有 `.yaml` 文件。

### 示例4：禁用某个子任务

编辑 `config/tasks/gold_log.yaml`，将子任务的 `enabled` 设置为 `false`：

```yaml
tasks:
  - task_id: "gold_grant_result_null"
    task_name: "金库授权结果非空检查"
    enabled: false  # 禁用此子任务
    sql_template: "gold_log_null_check"
    params:
      field: "gold_grant_result"
      display_name: "金库授权结果"
```

## 常见问题

### Q1: 如何理解"稽核任务"和"子任务"？

**A**: 
- **稽核任务（Audit Task）**：对应一个 YAML 配置文件，如 `gold_log.yaml`
- **子任务（Sub-task）**：配置文件中 `tasks` 列表里的每一项，对应一个具体的检查

例如：
```
稽核任务: 4A金库审批日志表稽核 (gold_log.yaml)
  ├── 子任务1: 金库授权结果唯一性检查
  ├── 子任务2: 金库授权结果非空检查
  └── 子任务3: 审批人ID条件非空检查
```

### Q2: --task 参数应该填什么？

**A**: `--task` 参数的值是 `config/tasks/` 目录下的 YAML 文件名（不含 `.yaml` 后缀）。

例如：
- `config/tasks/operation_log.yaml` → `--task operation_log`
- `config/tasks/gold_log.yaml` → `--task gold_log`

### Q3: 如何同时稽核多个任务？

**A**: 使用 `--all-tasks` 参数：
```bash
python main.py --all-tasks
```

### Q4: 如何修改时间范围？

**A**: 编辑 `config/config.yaml` 中的 `start_time` 和 `end_time`。

### Q5: 如何添加自定义参数？

**A**: 在子任务的 `params` 中添加任意参数，然后在SQL模板中使用 `{参数名}` 引用：

```yaml
tasks:
  - task_id: "custom_check"
    task_name: "自定义检查"
    enabled: true
    sql_template: "custom_check"
    params:
      field: "my_field"
      threshold: "100"        # 自定义参数
      unit: "ms"              # 自定义参数
```

SQL模板中使用：
```sql
SELECT COUNT(*) 
FROM {table_standard}
WHERE {field} > {threshold}  -- 使用自定义参数
```

### Q6: 配置文件的命名规则？

**A**: 
- 任务配置文件名 = 任务标识名 + `.yaml`
- 例如：`gold_log.yaml`（任务标识为 gold_log）
- 使用时：`python main.py --task gold_log`
- 文件名即为稽核任务的标识符

### Q7: 如何配置目录路径？

**A**: 在 `config/config.yaml` 中配置：

```yaml
tasks_dir: "./config/tasks"           # 任务配置目录
sql_templates_dir: "./sql_templates"  # SQL模板根目录
report_output_dir: "./output"         # 报告输出目录
log_output_dir: "./logs"              # 日志输出目录
```

所有路径都支持相对路径和绝对路径。

系统会按以下顺序查找任务配置：
1. `{tasks_dir}/任务名.yaml`（默认：`config/tasks/任务名.yaml`）

如果配置了自定义的 `tasks_dir`，系统会在该目录下查找。

## 最佳实践

### 1. 命名规范

- 任务ID使用下划线命名：`log_id_null`
- 任务名称使用中文：`日志ID非空检查`
- SQL模板使用表名前缀：`operation_log_null_check`
- 配置文件名使用小写字母和下划线：`operation_log.yaml`

### 2. 参数组织

将相关参数组织在一起：
```yaml
params:
  # 字段信息
  field: "log_id"
  display_name: "日志ID"
  
  # 检查条件
  condition: "dst_device_type != 'unknown'"
  
  # 阈值配置
  threshold: "100"
  unit: "ms"
```

### 3. 注释说明

在配置文件中添加清晰的注释：
```yaml
# 任务1：日志ID-唯一性检查
# 检查日志ID是否存在重复记录
- task_id: "log_id_uniqueness"
  task_name: "日志ID唯一性检查"
  enabled: true
  sql_template: "operation_log_uniqueness_check"
  params:
    field: "log_id"
    display_name: "日志ID"
```

### 4. 模块化配置

将不同类型的检查分组：
```yaml
tasks:
  # === 非空检查 ===
  - task_id: "log_id_null"
    ...
  
  # === 枚举值检查 ===
  - task_id: "log_source_enum"
    ...
  
  # === 条件检查 ===
  - task_id: "protocol_conditional_null"
    ...
```
