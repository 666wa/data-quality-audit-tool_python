# 多表稽核快速指南

## 一句话总结

**为每个表创建独立的配置文件和SQL模板目录，通过命令行参数指定要稽核的表。**

---

## 快速对比

| 方案 | 配置方式 | SQL模板 | 适用场景 | 推荐度 |
|------|---------|---------|---------|--------|
| **方案A** | 每表一个配置文件 | 每表一个目录 | 表结构差异大 | ⭐⭐⭐⭐⭐ |
| 方案B | 单个配置文件 | 共享模板 | 表结构相似 | ⭐⭐⭐ |
| 方案C | 每表一个配置文件 | 通用+专属 | 需要灵活性 | ⭐⭐⭐⭐ |

---

## 推荐方案：方案A

### 目录结构（一目了然）
```
config/tables/              # 每个表一个配置文件
├── operation_log.yaml      # 操作日志表
├── access_log.yaml         # 访问日志表
└── audit_log.yaml          # 审计日志表

sql_templates/              # 每个表一个SQL目录
├── operation_log/          # 操作日志表SQL
│   ├── null_check_stats.sql
│   └── enum_check_stats.sql
├── access_log/             # 访问日志表SQL
│   └── null_check_stats.sql
└── audit_log/              # 审计日志表SQL
    └── null_check_stats.sql
```

### 使用方式（简单直接）
```bash
# 稽核单个表
python3 main.py --table operation_log

# 稽核多个表
python3 main.py --table operation_log,access_log

# 稽核所有表
python3 main.py --all-tables

# 生成指定表的SQL
python3 main.py --gen-sql --table operation_log
```

## 添加新表的3个步骤

### 步骤1：创建表配置文件
```bash
# 复制现有配置作为模板
cp config/tables/operation_log.yaml config/tables/new_table.yaml

# 编辑配置
vim config/tables/new_table.yaml
```

**修改内容**：
```yaml
table_info:
  name: "new_table"                              # 改成新表名
  display_name: "新表显示名称"                    # 改成显示名称
  standard_table: "argus.new_table_standard"     # 改成实际表名
  error_table: "argus.new_table_error"           # 改成实际表名
  time_field: "create_time"                      # 改成时间字段
  primary_key: "id"                              # 改成主键字段
  template_dir: "new_table"                      # 改成模板目录名

audit_tasks:
  - field: id                                    # 改成实际字段
    checks:
      - null_check
  # ... 添加其他字段
```

### 步骤2：创建SQL模板目录
```bash
# 创建目录
mkdir -p sql_templates/new_table

# 复制通用模板
cp sql_templates/operation_log/*.sql sql_templates/new_table/

# 根据新表结构修改SQL
vim sql_templates/new_table/null_check_stats.sql
```

**修改SQL中的字段名**：
- 如果新表没有 `dst_device_type` 字段，删除相关逻辑
- 如果新表的时间字段不同，确保使用正确的字段名
- 如果新表的主键不同，修改 `log_id` 为实际主键

### 步骤3：执行稽核
```bash
# 测试新表稽核
python3 main.py --table new_table

# 查看报告
cat output/new_table_report_*.txt
```

## 配置文件模板

### 最小配置（必填项）
```yaml
table_info:
  name: "table_name"                    # 表标识（必填）
  display_name: "表显示名称"             # 显示名称（必填）
  standard_table: "db.table_standard"   # 标准表名（必填）
  error_table: "db.table_error"         # 错误表名（必填）
  time_field: "time_field_name"         # 时间字段（必填）
  template_dir: "table_name"            # SQL模板目录（必填）

audit_tasks:
  - field: field_name                   # 至少一个字段（必填）
    checks:
      - null_check                      # 至少一个检查（必填）
```

### 完整配置（包含可选项）
```yaml
table_info:
  name: "table_name"
  display_name: "表显示名称"
  description: "表的详细描述"           # 可选
  standard_table: "db.table_standard"
  error_table: "db.table_error"
  time_field: "time_field_name"
  primary_key: "id"                     # 可选，用于唯一性检查
  template_dir: "table_name"

audit_tasks:
  - field: field1
    checks:
      - null_check
      - uniqueness_check
  
  - field: field2
    checks:
      - enum_check
      - semantic_check

special_tasks:                          # 可选
  - name: table_count_statistics
    type: table_count
```

---

## 常用检查类型

| 检查类型 | 说明 | 适用字段 | SQL模板 |
|---------|------|---------|---------|
| `null_check` | 非空核查 | 所有必填字段 | null_check_stats.sql |
| `uniqueness_check` | 唯一性核查 | 主键、唯一标识 | uniqueness_check_stats.sql |
| `enum_check` | 枚举值核查 | 状态、类型等枚举字段 | enum_check_stats.sql |
| `semantic_check` | 语义抽查 | 文本字段（检查乱码） | semantic_check_stats.sql |
| `conditional_null_check` | 条件非空核查 | 有条件的必填字段 | conditional_null_check_stats.sql |

## 优势总结

✅ **配置清晰**：每个表独立配置，互不干扰  
✅ **易于扩展**：添加新表只需3步  
✅ **便于维护**：修改一个表不影响其他表  
✅ **团队协作**：不同人可以负责不同表  
✅ **报告独立**：每个表生成独立报告
