# 多表稽核支持方案设计

## 一、需求背景

当前系统只支持对单一表组（standard表 + error表）进行稽核。现在需要扩展系统，支持对多个不同的表进行数据质量稽核。

**核心问题**：
1. 不同表的字段结构不同，SQL模板不能通用
2. 不同表可能需要不同的稽核规则
3. 需要独立管理每个表的稽核配置
4. 报告需要区分不同表的稽核结果

---

## 二、设计方案

### 方案A：多配置文件方案（推荐）⭐

**核心思路**：为每个表创建独立的配置文件和SQL模板目录

#### 目录结构
```
data-quality-audit-py/
├── config/
│   ├── config.yaml                    # 全局配置（数据库连接等）
│   ├── tables/                        # 表配置目录
│   │   ├── operation_log.yaml         # 操作日志表配置
│   │   ├── access_log.yaml            # 访问日志表配置
│   │   └── audit_log.yaml             # 审计日志表配置
│
├── sql_templates/
│   ├── operation_log/                 # 操作日志表SQL模板
│   │   ├── null_check_stats.sql
│   │   ├── null_check_sample.sql
│   │   ├── enum_check_stats.sql
│   │   └── ...
│   ├── access_log/                    # 访问日志表SQL模板
│   │   ├── null_check_stats.sql
│   │   └── ...
│   └── audit_log/                     # 审计日志表SQL模板
│       └── ...
│
├── output/
│   ├── operation_log_report_*.txt     # 按表分别生成报告
│   ├── access_log_report_*.txt
│   └── audit_log_report_*.txt
```

#### 表配置文件示例 (config/tables/operation_log.yaml)
```yaml
# 操作日志表稽核配置
table_info:
  name: "operation_log"                           # 表标识
  display_name: "操作日志表"                       # 显示名称
  standard_table: "argus.bg_4a_operation_log_standard"
  error_table: "argus.bg_4a_operation_log_error"
  time_field: "generic_into_time"
  primary_key: "log_id"

# 稽核任务
audit_tasks:
  - field: log_id
    checks:
      - uniqueness_check
      - null_check
  
  - field: exec_result
    checks:
      - enum_check
      - null_check
  
  # ... 其他字段

special_tasks:
  - name: table_count_statistics
    type: table_count
```

#### 使用方式
```bash
# 稽核单个表
python3 main.py --table operation_log

# 稽核多个表
python3 main.py --table operation_log,access_log,audit_log

# 稽核所有表
python3 main.py --all-tables

# 生成指定表的SQL
python3 main.py --gen-sql --table operation_log
```

**优点**：
- ✅ 配置清晰，每个表独立管理
- ✅ SQL模板完全隔离，互不影响
- ✅ 易于扩展新表
- ✅ 可以并行稽核多个表
- ✅ 报告独立，便于查看

**缺点**：
- ❌ 需要为每个表创建完整的SQL模板目录
- ❌ 通用的检查类型（如null_check）会有重复代码

### 方案B：单配置文件 + 表分组方案

**核心思路**：在一个配置文件中定义多个表，SQL模板使用表名作为变量

#### 配置文件示例 (config/audit_tasks.yaml)
```yaml
# 全局配置
global_settings:
  default_time_field: "generic_into_time"

# 表定义
tables:
  - name: "operation_log"
    display_name: "操作日志表"
    standard_table: "argus.bg_4a_operation_log_standard"
    error_table: "argus.bg_4a_operation_log_error"
    time_field: "generic_into_time"
    
    # 该表的稽核任务
    audit_tasks:
      - field: log_id
        checks:
          - uniqueness_check
          - null_check
      - field: exec_result
        checks:
          - enum_check
  
  - name: "access_log"
    display_name: "访问日志表"
    standard_table: "argus.bg_4a_access_log_standard"
    error_table: "argus.bg_4a_access_log_error"
    time_field: "access_time"
    
    # 该表的稽核任务
    audit_tasks:
      - field: user_id
        checks:
          - null_check
      - field: access_type
        checks:
          - enum_check
```

#### SQL模板（共享）
```sql
-- sql_templates/null_check_stats.sql
-- 使用 {table_standard} 和 {table_error} 作为变量
WITH time_range AS (
    SELECT 
        toDateTime64('{start_time}', 3) AS start_ts,
        toDateTime64('{end_time}', 3) AS end_ts
),
all_logs AS ( 
    SELECT {field}, dst_device_type
    FROM {table_standard}
    WHERE {time_field} >= (SELECT start_ts FROM time_range) 
      AND {time_field} < (SELECT end_ts FROM time_range)
    UNION ALL 
    SELECT {field}, dst_device_type
    FROM {table_error}
    WHERE {time_field} >= (SELECT start_ts FROM time_range) 
      AND {time_field} < (SELECT end_ts FROM time_range)
)
-- ... 后续逻辑
```

**优点**：
- ✅ 配置集中，便于管理
- ✅ SQL模板可以复用
- ✅ 减少重复代码

**缺点**：
- ❌ 不同表的字段差异大时，SQL模板难以通用
- ❌ 配置文件会变得很大
- ❌ 特殊表的特殊逻辑难以处理

### 方案C：混合方案（灵活性最高）

**核心思路**：结合方案A和方案B的优点

1. **通用检查类型**（如null_check、uniqueness_check）使用共享SQL模板
2. **特殊检查类型**（如业务相关的检查）使用表专属SQL模板

#### 目录结构
```
data-quality-audit-py/
├── config/
│   ├── config.yaml                    # 全局配置
│   └── tables/                        # 表配置目录
│       ├── operation_log.yaml
│       ├── access_log.yaml
│       └── audit_log.yaml
│
├── sql_templates/
│   ├── common/                        # 通用SQL模板（所有表共享）
│   │   ├── null_check_stats.sql
│   │   ├── null_check_sample.sql
│   │   ├── uniqueness_check_stats.sql
│   │   └── ...
│   │
│   ├── operation_log/                 # 操作日志表专属模板
│   │   ├── exec_result_anomaly_check_stats.sql
│   │   └── locked_accounts_stats.sql
│   │
│   └── access_log/                    # 访问日志表专属模板
│       └── access_pattern_check_stats.sql
```

#### 模板查找逻辑
```python
def load_template(table_name, check_type):
    # 1. 先查找表专属模板
    table_template = f"sql_templates/{table_name}/{check_type}_stats.sql"
    if exists(table_template):
        return load(table_template)
    
    # 2. 再查找通用模板
    common_template = f"sql_templates/common/{check_type}_stats.sql"
    if exists(common_template):
        return load(common_template)
    
    # 3. 都没找到，报错
    raise TemplateNotFoundError()
```

**优点**：
- ✅ 兼顾灵活性和复用性
- ✅ 通用逻辑不重复
- ✅ 特殊逻辑可以定制
- ✅ 易于维护和扩展

**缺点**：
- ❌ 实现复杂度较高
- ❌ 需要明确的模板查找规则

## 三、推荐方案详细设计

**推荐使用方案A（多配置文件方案）**，原因：
1. 配置清晰，易于理解
2. 不同表完全隔离，不会相互影响
3. 实现简单，风险低
4. 便于团队协作（不同人负责不同表）

### 3.2 代码改动点

#### 1. ConfigManager 增强
```python
class ConfigManager:
    def load_table_config(self, table_name):
        """加载指定表的配置"""
        table_config_path = Path(self.config['tables_config_dir']) / f"{table_name}.yaml"
        # ... 加载逻辑
    
    def list_all_tables(self):
        """列出所有可用的表配置"""
        tables_dir = Path(self.config['tables_config_dir'])
        return [f.stem for f in tables_dir.glob("*.yaml")]
```

#### 2. AuditExecutor 增强
```python
class AuditExecutor:
    def __init__(self, db_executor, config, table_config, logger):
        self.table_config = table_config  # 新增：表配置
        self.templates_dir = Path('sql_templates') / table_config['table_info']['template_dir']
```

#### 3. main.py 增强
```python
def main():
    parser.add_argument('--table', help='指定要稽核的表名')
    parser.add_argument('--all-tables', action='store_true', help='稽核所有表')
    
    if args.all_tables:
        tables = config_manager.list_all_tables()
        for table in tables:
            run_audit_for_table(table)
    elif args.table:
        run_audit_for_table(args.table)
```



## 六、常见问题

### Q1: 如何快速为新表创建配置？
**A**: 使用配置生成工具（待开发）：
```bash
python3 tools/create_table_config.py --table new_table --template operation_log
```

### Q2: 不同表的SQL模板有很多重复，如何优化？
**A**: 可以考虑方案C（混合方案），将通用模板提取到 `sql_templates/common/`

### Q3: 如何生成所有表的汇总报告？
**A**: 使用 `--all-tables` 参数后，系统会自动生成汇总报告

### Q4: 表配置文件太多，如何管理？
**A**: 可以按业务模块分组：
```
config/tables/
├── operation/          # 操作相关
│   ├── operation_log.yaml
│   └── command_log.yaml
├── access/             # 访问相关
│   ├── access_log.yaml
│   └── login_log.yaml
└── audit/              # 审计相关
    └── audit_log.yaml
```
